# End-to-End Validation — 30 URLs (Sprint 3.4)

> **Purpose.** Sprint 3.4's acceptance criterion in `ROADMAP.md` was written when the plan assumed
> `/health` and the dashboard would already be live on Railway/Vercel by this point. Deployment
> (Sprint 3.3) was explicitly deferred by Hammad on 2026-08-13 ("we will do these last steps
> later"). The part of 3.4 that actually carries grade weight — does the retrained model correctly
> classify 30 real, unseen URLs through the full pipeline — does not depend on *where* the backend
> is hosted, only on it running and reachable. This run therefore executes against the local Docker
> stack (`docker compose up`, same image that would be deployed) via `POST /analyze`, exercising the
> complete path: lexical feature extraction → XGBoost → live VirusTotal lookup → log-odds fusion →
> SHAP → Postgres persistence → JSON response. The browser-extension-to-dashboard click-through
> (popup → "View Full Report" → scan detail page) is deployment-adjacent UI wiring, not a detection
> claim, and is deferred alongside 3.3 — it is exercised manually once a live URL exists.

## Method

- **15 phishing URLs**: sampled from the live OpenPhish feed (`https://openphish.com/feed.txt`,
  fetched 2026-08-13, 300 active entries at fetch time) — genuinely unseen, not present in
  training, evaluation, or holdout data, and not PhishTank (the training corpus's own source), to
  avoid any chance of source overlap. Sampled every 20th line for source diversity rather than the
  first 15 (which clustered on one hosting pattern).
- **15 legitimate URLs**: real, well-known sites, weighted toward deep paths specifically because
  that was D1's blind spot — a bare-homepage-only legitimate set would not test the fix.
- Each URL POSTed to the local backend's `/analyze` with empty browser signals (no extension in the
  loop — this isolates the URL-model + fusion pipeline's real-world accuracy; browser-signal fusion
  is already covered by `tests/unit/test_risk_fusion.py` and the interstitial's manual test).
- Verdict thresholds per `PROJECT_STATE.md`: `> 0.70` phishing, `0.40–0.70` suspicious, `< 0.40`
  legitimate — unseen-domain and OpenPhish links can go dead within minutes of being listed, so a
  `request_error` is recorded honestly rather than silently excluded.

## Results

See `ml/reports/e2e_validation.md` for the executed run: full URL list, expected vs. actual verdict,
risk %, and the confusion matrix, generated by `tests/e2e/run_system_test.py`.

**Acceptance:** ≥ 26/30 correct, with zero false positives among the deep-path legitimate URLs.
